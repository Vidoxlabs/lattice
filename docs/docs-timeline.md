## 2026-11-25, ET (finish run)

- Cleanup: deleted the handoff file, which carried an unresolved merge and duplicated the decision log, and made the work record the single resume point. Added a unit test that fails on an unresolved conflict marker in any tracked text file, because the lint script only looked under three source directories. Verified: `CI=1 npm run check`, 52 unit, 29 route and 64 browser tests passing.
- Transport security: dropped `includeSubDomains` from the strict transport header, which now reads `max-age=31536000` and applies to the canonical host only; `preload` stays out. The route test pins the exact value and the browser test reads the header on the canonical host. Verified: 52 unit, 29 route, 64 browser tests.
- Preview addresses: `preview_urls` is `false` until Cloudflare Access protects them, because an uploaded version otherwise gets a public address on the account's shared Workers subdomain. The route test follows whichever value is committed, and the owner's Access steps are in the setup checklist. Verified: 52 unit, 29 route, 64 browser tests.
- Deploy path and Workers Builds readiness: the documented build image carries neither the system libraries Chromium and WebKit need nor root access to install them, so production deploys from GitHub Actions on a successful `check` on `main`, publishing the artifact that run verified; Workers Builds stays documented as the alternative with its production and preview commands. `npm run test:browser` now installs the engines itself, adds the system packages only where root exists, and launches both so a missing library fails the build. Node stays pinned through `.nvmrc`. Verified: `CI=1 npm run check`, 52 unit, 29 route, 64 browser tests; `npx wrangler deploy --dry-run` and `npx wrangler versions upload --dry-run` both read the redirected configuration, 15 modules and 393 asset files, and exited without account access.
- Domains: the canonical-host redirect keeps the request path and drops the query string, so a `www` deep link lands on the same page and a parameter from a foreign hostname does not travel. The domains runbook records both zones in one account, the records to clear before the first deploy, and the four `curl -sI` checks. Verified: 53 unit, 29 route and 66 browser tests, including a redirect test for a deep link with a query string.
- Secrets, bindings and workflows: the setup record is one register naming each variable and secret, its home, its default and the exact command; the rate limiter moved into its own module so the bound, the unbound and the broken paths are all tested; the binding stays commented out with a placeholder because its identifier is account-scoped. Added `snapshot-refresh.yml`, which opens a draft pull request and never pushes to the default branch, and `live-smoke.yml`, which is gated on a repository variable and never prompts a provider. Every action is pinned to a commit with its version beside it, and a unit test parses all six workflows. Verified: 65 unit, 29 route and 66 browser tests.
- Self-update: the documentation proposal that would write status and notify the site still has no answers, so nothing changed there. The site carries a daily rebuild that posts to the deploy hook and does nothing while its secret is absent, and the setup record says why it lives in a second repository and when to delete it. Verified: 65 unit, 29 route and 66 browser tests.
- Naming: `docs/naming-inventory.md` counts every use of the group name over the tracked files and the built output, separates it from ordinary CSS and page-family vocabulary, names an owner per group and sets the change order upstream first. No visible copy changed; the one internal marker now reads `TODO(upstream)`. ADR-0005 records the deploy, preview and transport decisions, and ADR-0001 and ADR-0002 point at what changed.

- Follow-up on the same day: removed `scheduled-rebuild.yml` and the deploy hook with it. `check` now carries a daily schedule, a manual dispatch and a `docs-sync` repository dispatch, and `deploy` follows any successful `check` on the default branch from those triggers as well as from a push. Both account values became required secrets in a `production` environment restricted to the default branch, `CLOUDFLARE_ACCOUNT_ID` as a secret rather than a variable, and every checkout sets `persist-credentials: false`. The live smoke now follows a successful deploy instead of a push, so it checks the version that is actually live. Verified with `CI=1 npm run check` and with the workflow test that parses all five files.
